# D{0-1}背包问题求解器 - 代码规范说明

## 一、命名规范

### 1.1 类命名
- 使用 UpperCamelCase（大驼峰）风格
- 类名使用名词，首字母大写
- 抽象类以 Abstract 或 Base 开头
- 接口类以 I 开头或使用形容词形式

**示例：**
```java
public class KnapsackProblem { }
public class DynamicProgrammingSolver { }
public interface IDataExporter { }
```

### 1.2 方法命名
- 使用 lowerCamelCase（小驼峰）风格
- 方法名使用动词或动词短语
- 访问器方法以 get 或 is 开头
- 修改器方法以 set 开头

**示例：**
```java
public void solve() { }
public double getTotalValue() { }
public void setCapacity(double capacity) { }
```

### 1.3 变量命名
- 使用 lowerCamelCase（小驼峰）风格
- 变量名使用有意义的名词
- 布尔变量以 is 开头
- 避免使用单字母变量名（循环变量除外）

**示例：**
```java
private double capacity;
private List<ItemSet> itemSets;
private boolean isSorted;
```

### 1.4 常量命名
- 全部大写，单词间用下划线分隔
- 使用 static final 修饰
- 命名要表达完整的语义

**示例：**
```java
private static final int PRECISION_FACTOR = 100;
private static final String DATE_FORMAT = "yyyy-MM-dd HH:mm:ss";
```

### 1.5 包命名
- 全部小写
- 使用点分隔符，单词之间有且仅有一个自然语义的英语单词
- 包名使用单数形式

**示例：**
```
com.knapsack.model
com.knapsack.algorithm
com.knapsack.io
```

## 二、格式规范

### 2.1 缩进
- 使用 4 个空格缩进，不使用 Tab
- 缩进层级清晰，每层缩进 4 个空格

### 2.2 行宽
- 每行最多 120 个字符
- 超过限制时，在逗号或操作符后换行
- 换行后缩进 8 个空格

### 2.3 空行
- 类成员变量与方法之间空 1 行
- 方法之间空 1 行
- 逻辑块之间根据需要空行
- 文件末尾空 1 行

### 2.4 空格
- 操作符前后加空格
- 逗号后加空格
- 关键字后加空格
- 左括号前不加空格

**示例：**
```java
if (condition) {
    int result = a + b;
    List<String> list = new ArrayList<>();
}
```

## 三、注释规范

### 3.1 类注释
- 每个类必须有 Javadoc 注释
- 说明类的功能和用途

**示例：**
```java
/**
 * D{0-1}背包问题的数据模型类
 * 包含背包容量和项集列表
 */
public class KnapsackProblem { }
```

### 3.2 方法注释
- 公共方法必须有 Javadoc 注释
- 说明方法功能、参数、返回值

**示例：**
```java
/**
 * 使用动态规划算法求解D{0-1}背包问题
 * @param problem 背包问题实例
 * @return 求解结果
 */
public SolutionResult solve(KnapsackProblem problem) { }
```

### 3.3 行内注释
- 对复杂逻辑添加行内注释
- 注释放在代码上方，使用 // 格式
- 注释要简洁明了

**示例：**
```java
// 将浮点数转换为整数以提高精度
int intCapacity = (int) (capacity * PRECISION_FACTOR);
```

## 四、代码结构规范

### 4.1 类成员顺序
1. 常量
2. 静态变量
3. 实例变量
4. 构造方法
5. 公共方法
6. 私有方法

### 4.2 方法长度
- 单个方法不超过 50 行
- 复杂方法拆分为多个小方法
- 每个方法只做一件事

### 4.3 参数数量
- 方法参数不超过 5 个
- 参数过多时使用对象封装

## 五、其他规范

### 5.1 异常处理
- 不要捕获 Exception 或 Throwable
- 捕获具体异常类型
- 异常信息要清晰明确

### 5.2 资源管理
- 使用 try-with-resources 管理资源
- 确保资源正确释放

### 5.3 集合使用
- 指定集合泛型类型
- 使用接口类型声明变量

**示例：**
```java
List<ItemSet> itemSets = new ArrayList<>();
Map<String, Integer> map = new HashMap<>();
```

### 5.4 字符串处理
- 使用 StringBuilder 进行字符串拼接
- 避免在循环中使用 + 拼接字符串
